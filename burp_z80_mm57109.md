# BURP / Z80 ↔ MM57109 Interaction Notes (with call-site cross references)

This document summarises **how BURP (the PSI COMP-80 high-level language)** communicates with the **MM57109** from the Z80’s point of view.

It includes **cross-references to specific BURP call sites** in the combined Monitor+BURP ROM disassembly.

---

## 1. Ports and basic model

### Port `$60` — MM57109 output latch
- BURP writes command/data bytes via `OUT ($60),A`.
- Most writes occur via the MM57109 instruction output routine `$042E`, plus a few direct `OUT ($60),A` sites.


### Port `$03` — combined status + 4-bit data
- **Status:** BURP polls bits **5 (`$20`)** and **6 (`$40`)**.
- **Data:** during IM1 interrupts, BURP reads `$03` and stores **`A & $0F`** as a nibble.

---

## 2. Key routines

### `$042E` — MM57109_SEND_INSTRUCTION_IN_A

This waits for MM57109 to become RDY (RDY=0, active low).

``` asm
; Is MM57109 Ready?
0430: DB 03       IN A,($03)  ; poll status: IN A,($03), is the MM57109 Ready?
0432: E6 20       AND $20  ; mask RDY bit (bit5)
0434: 20 FA       JR NZ,$0430  ; wait while RDY==1 (until it goes low)
```

Sends the instruction to MM57109

``` asm
; Send instruction to MM57109
0436: 78          LD A,B  ; restore byte to send
0437: D3 60       OUT ($60),A  ; phase 1: OUT ($60),A
```
Waits for RDY=1, indicating that the instruction is executing

``` asm
; Wait for MM57109 to show it is executing the instruction (RDY=1 when it is busy executing, ie not ready)
0439: DB 03       IN A,($03)  ; poll for acknowledge: IN A,($03)
043B: E6 20       AND $20  ; mask RDY bit (bit5)
043D: 28 FA       JR Z,$0439  ; wait for RDY==1 (indication that the instruction is being executed)
```

Then sets HOLD. This causes the MM57109 to stop after the current instuction has completed (RDY=0)

``` asm
; Set the hold bit. This holds the MM57109 when it has completed the current instruction (ie when RDY=0)
043F: 78          LD A,B  ; restore byte to send
0440: F6 80       OR $80  ; set hold bit7
0442: D3 60       OUT ($60),A  ; Sets HOLD
```


### `$0446` — BURP_SEND_INLINE_MM57109_INSTRUCTIONS_UNTIL_FF
Reads bytes from the caller’s inline stream (at return address), sends each via `$042E` until `$FF` terminator.


```asm
0446: E3          EX (SP),HL
0447: 7E          LD A,(HL)
0448: 23          INC HL
0449: E3          EX (SP),HL
044A: FE FF       CP $FF
044C: C8          RET Z
044D: CD 2E 04    CALL $042E  ; MM57109_SEND_INSTRUCTION_IN_A(A=byte)

0450: 18 F4       JR $0446
0452: 23          INC HL
0453: 23          INC HL
0454: 7E          LD A,(HL)
```

### `$058A` — MM57109_SEND_AND_WAIT_RDDY_BR

Handles the MM57109 BR (branch) output which pulses low whenever one of the MM57109
branch instructions proves to be true.
Example instuctions are (passed in register A) are

```
      TJC*   0x10(o20) - Test Jump Conditional
      TX=0*  0x11(o21) - Test X=0
      TXLTO* 0x12(o22) - Test X < 0 
      TXF*   0x13(o23) - Test |X| < 1 i.e. test if x is a fraction
      TERR*  0x14(o24) - Test error flag 
```   

The subroutine starts the execution of the instruction in resgister A and then reads in
the 6 bit data word from the MM57109. The 4 digit out lines are blanked odd so that
only the READY and BR lines both initally high get through (0591). By continually reading
and jumping back on even parity the Z80 is effectively waiting for one of these two lines to become active.
If it is the BR line the Z80 outputs a NOP to the 57109 (because when tests prove true the 57109 
immediately looks for a new instruction and waits for its completion). 
If READY became active to indicate a failed test the last procedure is jumped. 
Finally the read in and masked byte which caused the exit from the parity check loop stored in register B 
as part of that loop is read into A and masked for bit 6 so that the state of the line and hence the zero flag in the F register is 
set on a successfil test.

Send a byte in A reg to the MM57109, then wait for a status condition on port $03, returns 


```asm
058A: C5          PUSH BC  ; PUSH BC (preserve)
058B: CD 2E 04    CALL $042E  ; MM57109_SEND_INSTRUCTION_IN_A(A=byte) ; send command/data
058E: DB 03       IN A,($03)  ; poll port $03 (status + DO bits)
0590: 47          LD B,A  ; B := raw port sample (latched for return)
0591: E6 60       AND $60  ; mask status bits RDY($20) and BR($40)
0593: EA 8E 05    JP PE,$058E  ; loop while parity-even => 0 or 2 bits set ($00 or $60); exit when $20 or $40
0596: FE 30       CP $30  ; if masked value >= $30, it's $40 (BR) (since $60 would not exit)
0598: 30 04       JR NC,$059E
059A: 3E 3F       LD A,$3F  ; else it is $20 (RDY): Output a NOP instruction
059C: D3 60       OUT ($60),A  ; Output a NOP instruction ...
059E: DB 03       IN A,($03)  ; wait for RDY to deassert (bit5==0)
05A0: E6 20       AND $20
05A2: 20 FA       JR NZ,$059E
05A4: 78          LD A,B  ; A := latched raw port value
05A5: E6 40       AND $40  ; keep only bit6 (BR/test/status)
05A7: C1          POP BC  ; POP BC
05A8: C9          RET  ; RET with A=$00 or $40 (Z/NZ)
```

### `$0038` — IM1 interrupt handler (nibble capture)
Each interrupt stores one nibble `($03 & $0F)` into `(HL)` and increments `HL`.

Interrupt handler for the MM57109 stores values in the address pointed to 
via the HL register, which should have been setup prior to interrups being 
enabled.


```asm
0038: F5           PUSH AF
0039: DB 03        IN A,($03)
003B: E6 0F        AND A,$0F
003D: 77           LD (HL),A
003E: 23           INC HL
003F: F1           POP AF
0040: FB           EI
0041: C9           RET
```

## 3. Memory areas used for MM57109 command/response exchange

### `$1FF4–$1FF7` — 4-nibble response/descriptor buffer
- BURP sets `HL=$1FF4`, enables **IM1**, then expects **four interrupts** to fill `$1FF4..$1FF7`.
- `$0460` is the key routine that sets this up and then consumes the nibbles.

### `$1E00–$1EFF` and `$1F00–$1FFF` — 16-byte working blocks
- BURP uses selector-based 16-byte blocks (via `$07AC`) and initializes them (via `$0714`).
- These appear to support higher-level formatting/operand staging around MM57109 operations.

`$0446` reads bytes starting at the **return address** (immediately after the `CALL $0446` instruction), and keeps sending them to the MM57109 until it encounters a terminator byte `$FF`.

| `$04D7` | `$04DA–$04DF` | `3C 01 02 06 3B` | 5-byte sequence (`DB $3C,$01,$02,$06,$3B,$FF`). Often followed by `$0460` item/response capture. |

## MM57109 Initalisation


It is initialised with a `MCRL` instruction 

> Clear all internal registers and memory; initialize
I/O control signals, MDC = 8, MODE = floating
point. (See INITIALIZATION.)

NOTE  Mantissa digit count (MDC), set by SMOC instruction, initially = 8
> 

followed by `TOGM` which toggles the mode. 

> Change mode from floating .point to scientific
notation or vice-versa, depending on present
mode. The mode affects only the I N and OUT
instructions. Internal calculations are always in
8-digit scientific notation.
> 

So the result is that we end up in **scientific notation** when using the MM57109 in BURP.
