COMP80 Emulator

The PSI COMP80, a Z80 computer published as a build-it-yourself series in Wireless World, running its monitor ROM with one of three languages in the top 2 KB: the original BURP, or the FORTH and LISP written for this project. Pick a ROM, then click the screen and type, or run one of the examples.

Using the emulator

The COMP80 starts in its monitor, which shows READY on the top line. Click the screen (or use the typing box on a phone) and type. The keyboard is upper case only; letters are sent as capitals whatever you type.

KeyOn the COMP80
ReturnEnd a line. The monitor itself doesn’t need it: a command runs once its last hex digit is typed.
^RS. At READY it enters the language in the ROM (BURP, FORTH or LISP). In FORTH and LISP it rubs out the last character.
BackspaceRubout in FORTH and LISP (the emulator sends RS for you).
Ctrl \FS: back to the monitor’s command state.
EscThe RESET key: restarts the monitor. Memory is kept, so RS gets back into FORTH or LISP with your words and functions still there.

Keys while a program runs

The keyboard interrupts the processor, and the monitor only accepts a key while the processor is waiting for one. A key pressed while a program is busy restarts the monitor, which is how you stop a program: press any key, then RS to get back into the language. Programs that read the keys, like Life, wait for them in the way the monitor expects.

Controls

  • ROM switches the language in the top 2 KB of the ROM. Switching powers the computer off and on, so memory is cleared.
  • Memory adds the 32 KB expansion at 8800–FFFF. LISP uses it for 7680 cells instead of 672; the others don’t need it.
  • Fast runs as fast as your browser can instead of at the real 4 MHz. Examples are typed in fast anyway.
  • Type in a program types pasted text a line at a time, waiting for FORTH or LISP to be ready for each line.

What isn’t emulated

There is no cassette interface or floppy disc, so READ, TAPE and the disc commands do nothing useful. Programs that came on tape are loaded straight into memory by the examples.

The monitor

The monitor fills the first 1 KB of the ROM and is the same whichever language is fitted. At READY, type a command and its addresses as four hex digits each, run together: LIST 1000, MOV 0BB50C000C00. The command appears on the top line as you type and runs as soon as its last digit is typed. A mistake can be abandoned with FS.

Memory

The ROM is 0000–0BFF (monitor 0000–03FF, language 0400–0BFF), read/write memory is 0C00–1FFF, and the screen is 2 KB at 8000, 64 characters by 32 lines. A screen byte below 40h is a letter or sign (A is 01, space 20, digits 30–39); 40h and up is one of 64 graphics characters, 4Fh a solid block.

Every line of the ROMs, annotated, and their hex dumps are on COMP80 ROM Listings: the monitor and all three languages, with each name and jump a link to the line it means.

The examples

  • Game of Life keeps 128 × 64 cells, four to a character using the quarter-block graphics, with edges that wrap. R starts a new random board, P pauses, S goes back to the monitor. It has to read keys while it runs, so it plays a trick on the monitor’s keyboard check: its stack is in ROM, where pushes are lost, and the return address the monitor finds there points at a HALT the program put in place.
  • The pictures recreate Fig. 22 of the August 1979 article from photos of the screen: a 16-byte loader copies a 2 KB picture to the screen and waits for a key.
  • ALPH and LIST show two of the monitor’s own commands.

BURP

BURP is the high-level language of the original ROM, from the Wireless World articles: a small BASIC-like language whose arithmetic is done by a National MM57109 scientific calculator chip. Press RS at READY and the top line changes to BURP. Commands end with a space.

The chip takes its time, as the real one did: an addition takes about 20 ms, a logarithm 0.3 s and a sine half a second. Type a key only when BURP is waiting for one; a key while it is busy restarts the monitor.

Commands

CommandWhat it does
LIST nLists the program from line n, then shows the end address of the program in memory (programs live from 0C00 to 1DC0).
RUN nRuns from line n. Any key stops it, back to READY; RS returns to BURP.
ADDAdds lines, each typed with its number and ended with Return. End the last line with a colon instead of Return: that leaves ADD and marks the end of the program.
DEL nDeletes line n and lists what is left.
LOADStarts a new program, typed and ended like ADD.

The sample program

The ROM holds the articles’ sample program at 0BB5. At READY, MOV 0BB50C000C00 copies it to the program area, RS enters BURP, and LIST 5 shows it:

005 FOR A=1 STEP 1 UNTIL 25
006 LET L=A LOG
007 PRINT A0 L8
008 NEXT A
009 END
0C4A

RUN 5 prints the common logarithms of 1 to 25. The articles go on to change line 6 with DEL 6 , then ADD and 6 LET L=A ROOT : for square roots, or 6 LET L=A EX : for ex. From e19 the results no longer fit in 8 digits and BURP prints them in scientific notation, the exponent at the end: 7.2004899 10 for e25.

The examples

  • BURP sample program copies the program from ROM, lists it and runs it.
  • e to the x follows the articles: it changes line 6, adds a heading line and runs from line 4.
  • Sines and cosines types in a new program with LOAD: a FOR loop with STEP 0.5 calling a subroutine, then a negative number and a division.

FORTH

A small FORTH, written for this project, in the 2 KB that held BURP. Press RS at READY; the top line changes to FORTH and a _ cursor appears. Type a line and press Return: it runs and FORTH prints OK. Numbers are 16-bit integers.

  • A word can call itself: : FACT DUP 1 > IF DUP 1- FACT * ELSE DROP 1 THEN ;
  • EMIT prints ASCII; 128 + n prints graphics character n, so 143 EMIT is a solid block.
  • col row AT moves the print position (0–63, 0–31); PAGE clears lines 1–31.
  • KEY waits for a key and returns its code (13 for Return).
  • COLD forgets your words; BYE goes to the monitor.
  • An unknown word prints WORD ?; taking more off the stack than there was prints EMPTY.

The examples

  • Game of Life in FORTH plays on 64 × 31 cells, one per character, reading the board straight from screen memory. It adds up columns of three cells first, so each cell takes three additions; a generation takes about 3 s. 1000 LIFE runs 1000 generations.
  • Mandelbrot set in FORTH draws one point per character, shaded by how many steps it takes to escape, with the set in solid blocks. With only 16-bit integers it works in fixed point with 90 as 1.0. MANDEL takes about 95 s.

LISP

A small LISP 1.5 style interpreter, written for this project, in the 2 KB that held BURP, with garbage collection and dynamic scope. Press RS at READY; the top line changes to LISP. Type an expression and press Return to see its value. An expression can run over several lines: LISP keeps reading until the brackets balance.

GroupBuilt-ins
Special formsQUOTE (and 'x) COND LAMBDA DEFUN SETQ AND OR
ListsCAR CDR CONS LIST CADR CADDR
TestsATOM EQ NULL NUMBERP (true is T, false NIL)
Arithmetic+ - * / REM < >, two arguments each
OutputPRINT PRIN1 TERPRI TYO
OtherEVAL GC
  • Numbers are integers from −16384 to 16383. EQ compares numbers too.
  • (DEFUN SQ (X) (* X X)) sets SQ to (LAMBDA (X) (* X X)). A function is a value: (MAPCAR SQ L) passes it, and (F X) calls whatever F holds.
  • Variables are dynamically scoped, as in the original LISP: a function sees the variables of whatever called it, unless it has a parameter of the same name.
  • (PRINT x) prints x and a new line, (PRIN1 x) without one, (TERPRI) starts a new line and (TYO n) prints character code n. (GC) returns the number of free cells.
  • ; starts a comment. Errors print a message and the culprit: UNBOUND FOO, BAD FN 1, BAD ARG A, TOO DEEP, NO MEM.
  • Without the expansion there are 672 cells and recursion goes about 45 calls deep; with it, 7680 cells and about 140.

The examples

  • Symbolic differentiation is the program LISP was made for: an expression is a list, so DERIV can take it apart and build its derivative. (DERIV '(+ (* 3 (EXPT X 2)) (* 2 X)) 'X) gives (+ (* 6 X) 2).
  • Towers of Hanoi: move all but the bottom disc out of the way, move the bottom disc, move the rest back on top. (HANOI 4 'A 'C 'B) prints 15 moves.
  • Eight queens puts a queen in the first safe row of each column and backs up when a column has none. N is never passed to the inner functions: dynamic scope finds the N that QUEENS was called with.
The emulator follows the MAME driver in the psicomp80 repository: a Z80 at 4 MHz, the 3 KB ROM typed in from the magazine’s hex listing, a 64 × 32 character screen and the keyboard on an NMI. It has no cassette or floppy disc; programs that came on tape are loaded straight into memory.
