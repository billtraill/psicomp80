COMP80 v2 Hardware

The 1979 PSI COMP80 took a 16 × 12 inch board and more than 300 parts. This is the same computer on a 75 × 55 mm board with 64 parts, almost all of them passives round one Raspberry Pi RP2350 microcontroller. It runs the original ROM images unchanged: the monitor and BURP, and the FORTH and LISP ROMs, loaded from a microSD card. The display goes out over HDMI, you type on any USB keyboard, and it runs from a USB-C supply.

Nothing of the original circuit is left. The RP2350 runs a Z80 emulator and models the MM57109 calculator chip and the tape interface. It draws the screen in the original character set. See the original board, the v3 board (the COMP80 in an FPGA), the emulator and the ROM listings.

From

Routed by Freerouting after the supply pins were laid by hand: 647 track segments, 143 vias. KiCad's design check finds no errors.

How it works

The ROMs only ever see the Z80, its memory and six I/O ports. If those behave as they did in 1979, the ROMs can't tell the difference, so the RP2350 provides exactly those and nothing more.

What became of the 1979 board

One chip for three hundred

Each part of the original circuit is either something the RP2350 does in software or something a modern connector does better. The table goes section by section through the original board.

The emulation is exact where the ROMs can see it. The Z80 is a full instruction-set emulator with every instruction's T-states. It runs its 2 MHz in 1 ms slices against the RP2350's timer, so the ROMs' delay loops, the 300 baud tape timing and BURP's waits on the calculator chip all take their real time. The MM57109 is the same model as the MAME driver's and the web emulator's: it pulses its R/W line once per digit and interrupts the Z80, and every instruction takes the chip's own execution time.

The microcontroller

The is Raspberry Pi's microcontroller, with two Arm Cortex-M33 cores, 520 KB of RAM, a high-speed serial port (HSTX) that can drive HDMI directly, and programmable I/O state machines (PIO). Its program lives in the 4 MB QSPI flash , and a 12 MHz crystal clocks it.

The chip makes its own 1.1 V core supply with an on-chip switching regulator. That takes the inductor , which sits straight below the regulator pins, and the filtered supply from and . Each supply pin has a 0402 capacitor beside it; those pins are 0.4 mm apart, too close for anything bigger.

The firmware runs the chip at 240 MHz with the core at 1.2 V. That is above the 150 MHz rating, as most RP2350 video projects run it. PIO-USB needs a multiple of 48 MHz, and HDMI needs its own 126 MHz clock, which comes from the second PLL.

Hold while pressing , and the RP2350 shows up on the USB-C port as a drive. Copy comp80v2.uf2 onto it to load the firmware.

HDMI

The RP2350's HSTX port has a TMDS encoder built in, so eight GPIOs can drive an HDMI socket's three data pairs and its clock pair directly. Each line has a 270 Ω resistor (–) into the display's terminations. What goes out is DVI, video without sound, which every HDMI input accepts.

The picture is 640 × 480 at 60 Hz. The COMP80 showed 64 × 32 characters of 6 × 10 dots on a 4:3 television, and 640 × 480 fits that exactly with each character cell drawn 10 × 15 pixels. The dot columns are 1, 2, 2, 1, 2, 2 pixels wide, so the 5-dot letters come out symmetrical. The font is the MAME driver's, and so are the 64 graphics characters.

Core 0 runs the DMA that feeds the HSTX, so it never waits on the USB stack. Core 1 compares the 2K of screen memory with what it last drew and redraws only the characters that changed.

The USB keyboard

The RP2350's own USB goes to the USB-C socket, for loading firmware. The keyboard has its own USB-A socket, run by PIO-USB, a USB host made from two GPIOs and a PIO state machine, with TinyUSB's host stack on top. The 15 kΩ pull-downs and are what a host puts on D+ and D−. limits the keyboard's 5 V.

Keys become the codes the COMP80's own keyboard gave, the same mapping as the web emulator: letters in capitals, Return, Backspace (rub-out in FORTH and LISP), Ctrl+\ for FS. Each key is latched for IN 01 and raises the Z80's NMI. That is how the original keyboard woke a program waiting in HALT, and how a key pressed while a program runs resets it. Esc is the RESET key.

ROMs and tapes on microSD

The card works in SPI mode on SPI1, with pull-ups on every data line (–), and holds a FAT or exFAT file system. At power-on the firmware loads the ROM named in COMP80.CFG into 0000–0BFF. The set-up screen lists every .ROM in the folder. With no card, it runs the monitor and BURP ROM built into the firmware.

Tapes are WAV files, the format the MAME driver records. The COMP80's tape interface handed the Z80 one decoded bit each way, so a tape here is that bit against time. Playing feeds IN 00 through a Schmitt trigger, like the driver's; recording writes what OUT 20 sends as a square wave. READ, TAPE and the FORTH and LISP tape words all work as they did on cassette, at the same speed.

Tape speed follows the Z80 clock. The ROM's timing loops were written for the real machine's 2 MHz; the MAME driver and the web emulator run at 4 MHz, so tapes recorded there play at twice the baud rate. Set the clock to 4 MHz to load them. Tapes recorded on this board at 2 MHz are true to the original.

Power

The USB-C socket has 5.1 kΩ resistors on both CC pins (, ), which ask any USB-C supply for 5 V, including a laptop's port. The AP2112K makes 3.3 V for everything; the 3.3 V plane on inner layer 2 carries it. The whole board draws well under half an amp, keyboard included.

The same socket's data pins go to the RP2350's USB through and , so one cable powers the board and reloads its firmware.

The firmware

C, with Raspberry Pi's Pico SDK, TinyUSB, Pico-PIO-USB and FatFs. It's in hardware_v2/firmware/, with a built comp80v2.uf2.

The Z80 and the machine around it are a port of the web emulator's, which is checked against MAME line by line. The port was tested the same way. Built for the Mac, it runs every LISP, FORTH and BURP test session and prints screens identical to the web emulator's. It loads life.wav through the tape model byte for byte, and a tape it records loads back the same.

The code that touches the hardware compiles for the RP2350: HDMI, the USB host, the SD card and the clock set-up. It has not run on a board yet, because no board has been made.

  • z80.c, comp80.c: the Z80, the memory map, the ports and the MM57109
  • tape.c: WAV tapes on IN 00 and OUT 20
  • video.c: HSTX, its DMA, and drawing the characters
  • keyboard.c: TinyUSB host, boot-protocol keyboards
  • sdcard.c, storage.c: the card in SPI mode, FatFs, settings
  • menu.c, main.c: the set-up screen, start-up and pacing
  • host/: the Mac build and the comparison with the web emulator

What to know

  • Not built yet. The board passes KiCad's design check and the firmware compiles, but neither has met real hardware. The first board should be checked supply by supply before the RP2350 goes on.
  • Assembly. The RP2350 is a 0.4 mm pitch QFN and the capacitors beside it are 0402, so the board wants a stencil and reflow, or a PCB assembly service. Everything else is 0603 or larger.
  • Four layers, 0.15 mm tracks with 0.12 mm gaps, and 0.45 mm vias with 0.2 mm holes beside the supply pins: standard for four-layer boards from the usual makers.
  • HDMI is DVI. Some televisions are slow to lock onto a DVI signal, or want 640 × 480 set as a PC input. Monitors and capture devices take it without fuss.
  • Not carried over: the teleprinter port (OUT 00), the floppy disc, and real cassettes. Use WAV files; any audio tool can convert an old cassette recording to one.
The board is a KiCad project in the repository's hardware_v2/ folder: tools/design.py holds the parts and connections, tools/make_board.py builds the board, and this page is made by tools/make_page.py.
