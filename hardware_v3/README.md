# COMP80 v3: the COMP80 in an Artix-7 FPGA

The COMP80 built again in logic, in an AMD Artix-7 XC7A100T. A Verilog Z80 and its
64 KB of memory, the I/O ports, the keyboard latch and NMI, and the display are all
logic. A PicoRV32 RISC-V soft processor in the same FPGA reads the microSD card,
models the MM57109 and the cassette, and turns USB keyboard reports into key codes.
The outside is v2's, HDMI, USB keyboard, microSD and USB-C power, plus a second
USB-C socket that sends the screen to a USB-C monitor as DisplayPort. The web page is
`../hardware_v3.html`.

The bitstream builds in Vivado and meets timing; no board has been made yet.
`VIVADO_TODO.md` has the build steps, what the reports showed and the bring-up
checklist. `SETUP.md` covers a built board: programming it, the microSD card, the keys,
the serial console and the USB-C monitor.

| `firmware/` | The soft processor's firmware: `main.c`, `pd.c` (USB Power Delivery and DisplayPort alternate mode through the FUSB302), `sd_spi.c`, `hw.h`, plus v2's `mm57109.c`, `tape.c` and `storage.c`. `firmware.hex` is the built RAM image |
| `sim/` | Verilator and Icarus Verilog testbenches |
| `vivado/build.tcl` | The Vivado build: bitstream and flash image |
| `tools/` | `design.py` (the board), `make_board.py` (KiCad), `fetch.sh` (outside HDL), `synth.sh` (yosys), `make_font.py`, `make_page.py` |
| `kicad/` | The KiCad 10 board: six layers, routed and filled. KiCad's DRC: no errors |

Outside HDL, fetched into `build/` by `tools/fetch.sh` at fixed commits: TV80 (MIT),
PicoRV32 (ISC), usb_hid_host (Apache-2.0), DisplayPort_Verilog (MIT), and FatFs for
the firmware.

## Tests

```bash
cd hardware_v3/sim && make test
```

This runs LISP, FORTH and BURP sessions on the logic and on v2's C core and compares
the screens: they match. It takes about a minute each.

```bash
cd hardware_v3/sim && make boot
```

This boots the soft processor's firmware with the machine. It prints `COMP80 v3`,
loads the built-in ROM and reaches READY.

```bash
cd hardware_v3/sim && iverilog -g2012 -DSIM -o video_tb video_tb.v ../rtl/video.v ../rtl/hdmi_out.v && vvp video_tb +screen=screen.hex
```

This draws one HDMI frame from a 2 KB screen dump (v2's `host/session` writes one
with `SCREEN=file`) and checks every TMDS symbol.

```bash
cd hardware_v3/sim && iverilog -g2012 -o dp_tb dp_tb.v ../rtl/dp_comp80_source.v ../build/DisplayPort_Verilog/src/test_streams/insert_main_stream_attrbutes_one_channel.v && vvp dp_tb +screen=screen.hex && python3 dp_decode.py screen.hex
```

The same for DisplayPort: it runs the COMP80 DisplayPort source and the core's
stream-attribute inserter on the screen dump and `dp_decode.py` turns the lane symbols back into a frame
(`dp_frame.png`) and compares it pixel by pixel.

```bash
sh hardware_v3/tools/synth.sh
```

This runs yosys for the XC7A100T. The design comes to about 5,900 LUTs, 3,600
flip-flops and 50 block RAMs, plus the four GTP transceivers.

## The board

110 × 84 mm, six layers: signals outside, then ground, 3.3 V, 1.0 V and 1.8 V planes,
with islands under the BGA for the transceivers' 1.0 V and 1.2 V and for bank 35's
2.5 V. The
XC7A100T in FGG484, a 16 MB SPI flash for its configuration, a 100 MHz oscillator,
and three TLV62569 bucks (1.0, 1.8, 3.3 V) from USB-C. It has HDMI straight from
TMDS_33 outputs, a USB-A socket for the keyboard, microSD, a 6-pin JTAG header, a
serial header, RESET and PROG buttons, and HALT and DONE LEDs.

The second USB-C socket (J7) is for a monitor. A FUSB302B handles USB Power
Delivery, a TPS2051C switches 5 V out to the monitor, and the FPGA's four GTP
transceivers drive the socket's four high-speed pairs from a 135 MHz oscillator.
Two LDOs give 2.5 V (the bank with the AUX channel) and 1.2 V (MGTAVTT).

Along the bottom edge, in silkscreen: the COMP80's screen as drawn on the cover of
the kit leaflet, the name and version, and its line from the 1979 original through
v2.

```bash
cd hardware_v3/tools && /Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 make_board.py
```

```bash
cd hardware/tools && /Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 route_board.py --pcb ../../hardware_v3/kicad/comp80v3.kicad_pcb --freerouting freerouting-2.5.0.jar --java /opt/homebrew/opt/openjdk/bin/java --passes 60
```

Then run it again with `--keep` added, which keeps what's routed and works on the
rest. `make_board.py` lays the hardest parts first: the BGA's breakout vias, the
plane and island vias, J7's escape vias, and HDMI's ground comb and escape vias.
Freerouting usually leaves a few connections; run KiCad's DRC to list them, and
finish each net with the grid router at v3's clearances (0.3 mm tracks for VBUS):

```bash
cd hardware/tools && GRID=0.05 CLEAR=0.15 TRACK=0.15 /Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 finish_routes.py --pcb ../../hardware_v3/kicad/comp80v3.kicad_pcb VIDEO_VBUS
```

## Firmware

```bash
cd hardware_v3/firmware && make
```

This needs a RISC-V GCC (xPack `riscv-none-elf-gcc` 15) and `build/fatfs`. It writes
`firmware.hex`, which goes into the bitstream as the soft processor's RAM contents.
