Using the emulator

The COMP80 starts in its monitor, which shows READY on the top line. Click the screen (or use the typing box on a phone) and type. The keyboard is upper case only; letters are sent as capitals whatever you type.

KeyOn the COMP80
ReturnEnd a line. The monitor itself doesn’t need it: a command runs once its last hex digit is typed.
^RS. At READY it enters the language in the ROM. In the languages that read a line it rubs out the last character; in CHIP-8 it starts the program again.
BackspaceRubout in the languages that read a line (the emulator sends RS for you).
Ctrl \FS: back to the monitor’s command state.
EscThe RESET key: restarts the monitor. Memory is kept, so RS gets back into FORTH or LISP with your words and functions still there.

Keys while a program runs

The keyboard interrupts the processor, and the monitor only accepts a key while the processor is waiting for one. A key pressed while a program is busy restarts the monitor, which is how you stop a program: press any key, then RS to get back into the language. Programs that read the keys, like Life, wait for them in the way the monitor expects.

Controls

  • ROM switches the language in the top 2 KB of the ROM. Switching powers the computer off and on, so memory is cleared.
  • Memory adds the 32 KB expansion at 8800–FFFF. LISP uses it for 7680 cells instead of 672, and Prolog for a 30 KB heap; the others don’t need it.
  • Fast runs as fast as your browser can instead of at the real 4 MHz. Examples are typed in fast anyway.
  • Type in a program types pasted text a line at a time, waiting for the computer to be ready for each line. In BURP it types the lines in with LOAD.

What isn’t emulated

There is no cassette interface or floppy disc, so READ, TAPE and the disc commands do nothing useful. Programs that came on tape are loaded straight into memory by the examples.

The monitor

The monitor fills the first 1 KB of the ROM and is the same whichever language is fitted. At READY, type a command and its addresses as four hex digits each, run together: LIST 1000, MOV 0BB50C000C00. The command appears on the top line as you type and runs as soon as its last digit is typed. A mistake can be abandoned with FS.

Memory

The ROM is 0000–0BFF (monitor 0000–03FF, language 0400–0BFF), read/write memory is 0C00–1FFF, and the screen is 2 KB at 8000, 64 characters by 32 lines. A screen byte below 40h is a letter or sign (A is 01, space 20, digits 30–39); 40h and up is one of 64 graphics characters, 4Fh a solid block.

Every line of the ROMs, annotated, and their hex dumps are on COMP80 ROM Listings: the monitor and all ten languages, with each name and jump a link to the line it means. The board itself, its circuits and its parts are on COMP80 Hardware.

The examples

  • Game of Life keeps 128 × 64 cells, four to a character using the quarter-block graphics, with edges that wrap. R starts a new random board, P pauses, S goes back to the monitor. It has to read keys while it runs, so it plays a trick on the monitor’s keyboard check: its stack is in ROM, where pushes are lost, and the return address the monitor finds there points at a HALT the program put in place.
  • Plasma fills the screen with flowing bands of shading. Each character is the sum of four sine waves, two across, one down and one diagonal, looked up in a 256-byte table and turned into one of six shades made of quarter blocks. The two waves across are worked out once a frame, so each character takes 89 T-states and it runs at about 20 frames a second.
  • Memory dump shows 30 lines of 16 bytes, in hex and as characters. N and B page through memory, D and U move a line, G and four hex digits go to an address, and Q goes back to the monitor. Like the Game of Life, it keeps its stack pointer in ROM so it can take a key at any moment, but it uses a word in the monitor itself, so it works with any of the ROMs.
  • Fire gives each character a heat. Two hidden rows below the screen get random heat every frame, and each cell becomes the average of the three below it and the one two below, less a little for cooling, looked up in one 256-byte table, so the flames flicker up and die away. It uses the plasma’s six shades and runs at about 11 frames a second.
  • Scrolling banner moves a message in big letters across the middle of the screen. Each dot of the 5 × 7 letters is two characters wide and one tall, so it is nearly square, and it scrolls half a character at a time, as a character can show the right half of one dot and the left half of the next. The message is text at 1400 ending with 00: LOAD 1400 [HELLO THERE ]00@ changes it.
  • The pictures recreate Fig. 22 of the August 1979 article from photos of the screen: a 16-byte loader copies a 2 KB picture to the screen and waits for a key.
  • ALPH and LIST show two of the monitor’s own commands.

BURP

BURP, short for Basic Using Reverse Polish, is the high-level language of the original ROM, from the Wireless World articles: a small BASIC-like language whose arithmetic is done by a National MM57109 scientific calculator chip. Expressions are written in reverse Polish notation, the order the chip takes them: LET X=X 1 + rather than X+1. Press RS at READY and the top line changes to BURP. Commands end with a space.

The chip takes its time, as the real one did: an addition takes about 20 ms, a logarithm 0.3 s and a sine half a second. Type a key only when BURP is waiting for one; a key while it is busy restarts the monitor.

DEL nDeletes line n and lists what is left.

The sample program

The ROM holds the articles’ sample program at 0BB5. At READY, MOV 0BB50C000C00 copies it to the program area, RS enters BURP, and LIST 5 shows it:

005 FOR A=1 STEP 1 UNTIL 25
006 LET L=A LOG
007 PRINT A0 L8
008 NEXT A
009 END
0C4A

RUN 5 prints the common logarithms of 1 to 25. The articles go on to change line 6 with DEL 6 , then ADD and 6 LET L=A ROOT : for square roots, or 6 LET L=A EX : for ex. From e19 the results no longer fit in 8 digits and BURP prints them in scientific notation, the exponent at the end: 7.2004899 10 for e25.

The examples

  • BURP sample program copies the program from ROM, lists it and runs it.
  • e to the x follows the articles: it changes line 6, adds a heading line and runs from line 4.
  • Sines and cosines types in a new program with LOAD: a FOR loop with STEP 0.5 calling a subroutine, then a negative number and a division.
  • Sierpiński triangle prints Pascal’s triangle mod 2, which is the Sierpiński triangle, as 1s and 0s. Every PRINT is a line of its own, so each row is a single number whose digits are the cells. Row r is the product of 11, 101 and 10001 for the bits 1, 2 and 4 set in r, since (1 + x)r mod 2 is the product of 1 + x2b over those bits, here with x = 10. The bottom eight rows are the top eight twice; they print as two numbers, as the chip holds only 8 digits.
  • Collatz sequence: halve an even number, treble an odd one and add 1. Nobody has proved it always reaches 1. INPUT waits for a number and a space; the sequence is printed eight to a line by shifting each value through A to H, since a PRINT is always a whole line. BURP has no INT, so to test for an even number it halves it, adds 10000000 and takes it away again: the chip rounds to 8 digits, which drops the fraction. 27 takes 111 steps and about three minutes.
  • Primes by trial division tries each odd number against the odd divisors up to its square root, with the same rounding trick, and prints the 25 primes below 100 in about two minutes. Line 30 sets the limit; BURP manages about ten statements a second.
  • Approximating π adds up the Leibniz series 4 − 4/3 + 4/5 − …, which is still 8333 millionths out after 120 terms, then the Nilakantha series 3 + 4/(2·3·4) − 4/(4·5·6) + …, which is within 113 millionths after 12. The error is against the chip’s own PI key.
  • Guess the number: BURP answers each guess with 1 (go higher), −1 (go lower) or 0 when you are right, with the number of guesses. The ROM has no random numbers, so you type any number first and the sine of it picks BURP’s number.
  • Loan repayments asks for the loan, the yearly rate in per cent and the years, works out the monthly payment and prints a year-by-year table of interest, capital repaid and balance owing, and the total paid. The 0.02 left at the end of 50000 at 8% over 20 years is the 8-digit chip.
  • Square roots by Newton’s method: start with the number itself as the guess, and keep replacing the guess with the average of it and the number divided by it; each step about doubles the correct digits. It stops when a guess repeats and then prints what the chip’s own ROOT gives, which can differ in the last digit: 1.4142135 against 1.4142136 for 2.
  • GCD and LCM follows Euclid: divide the larger number by the smaller, keep the remainder, and repeat with the smaller number and the remainder until it is 0; the last divisor is the greatest common divisor. Each division prints as a line, such as 1071 = 2 * 462 + 147. The quotient is rounded by adding and taking away 10000000, and taken back by one if the remainder comes out negative. The least common multiple is A / GCD * B.
  • Perfect numbers: a number is perfect when its divisors add up to itself, as 1 + 2 + 3 = 6. Adding up divisors would take BURP an hour just to reach 496, so this uses Euclid’s rule: when 2p − 1 is prime, 2p−1(2p − 1) is perfect. For p from 2 to 13 it tries odd divisors up to the square root, printing a factor or the perfect number: 6, 28, 496, 8128 and 33550336, which just fits in 8 digits. About 80 s.
  • Day of the week uses Zeller’s congruence: with January and February counted as months 13 and 14 of the year before, the day is (d + ⌊13(m + 1)/5⌋ + K + ⌊K/4⌋ + ⌊J/4⌋ + 5J) mod 7, where J is the century and K the year within it, 0 meaning Saturday. A subroutine at line 200 rounds down by rounding with 10000000 and taking off 1 if that went up, and a chain of IFs prints the name. 20 7 1969, the Moon landing, was a Sunday.
  • Factorials and e: 1! to 14!; from 12!, 479001600, there are more than 8 digits and BURP switches to scientific notation, 4.7900160 08. Then e as 1 + 1/1! + 1/2! + 1/3! + …, with its error against the chip’s 1 EX in hundred-millionths: after 10 terms the next term is too small to change the 8 digits, and the sum stops at 2.7182819, 1 out in the last place.

FORTH

The examples

  • Game of Life in FORTH plays on 64 × 31 cells, one per character, reading the board straight from screen memory. It adds up columns of three cells first, so each cell takes three additions; a generation takes about 3 s. 1000 LIFE runs 1000 generations.
  • Mandelbrot set in FORTH draws one point per character, shaded by how many steps it takes to escape, with the set in solid blocks. With only 16-bit integers it works in fixed point with 90 as 1.0. MANDEL takes about 95 s.
  • Sierpiński triangle in FORTH draws Pascal’s triangle mod 2: entry x of row y is odd when the bits of x are all set in y, which is one AND. It has 64 rows, each entry two cells wide, four cells to a graphics character, and fills the whole screen, title line too; a key clears it and puts the title back. SIER takes about 10 s.
  • Hilbert curve in FORTH is drawn by a turtle that knows its position and direction and can turn and step. A Hilbert curve of level n is four of level n − 1: turn, draw one mirrored, step, turn back, draw one, step, draw one, turn back, step, draw one mirrored, turn. HIL does exactly that, calling itself four times, with the sign of its angle doing the mirroring. Level 5 is 32 × 32 points, 4 cells apart across and 2 down so the curve comes out square, over the whole screen. HILBERT takes about 10 s; a key clears it.
  • Towers of Hanoi in FORTH moves the discs the same way as the LISP version: N − 1 discs out of the way onto the spare peg, disc N across, then the N − 1 back on top of it. HAN takes the two pegs as one number, from × 3 + to, so it only has two things on the stack to juggle; the spare peg is 3 − from − to. Each move is animated by writing the disc straight to screen memory a step at a time and putting back the peg behind it. 6 HANOI makes 63 moves in about 75 s; up to 10 HANOI fits on the screen. SPEED sets the pause between steps (300 to start with): 100 SPEED ! is faster.
  • Dragon curve in FORTH is a strip of paper folded in half 9 times and opened out. The same turtle as the Hilbert curve makes 512 steps; after step i it turns left when the bit above the lowest set bit of i is 0, and right when it is 1. DRAGON takes about 4 s.
  • Koch snowflake in FORTH replaces each side of a triangle with four sides a third as long, with a point in the middle, three times over. The turtle has six directions: 2 cells up or down, or 3 across and 1 up or down, which allowing for the shape of the cells are almost the same length and 60° apart. KOCH takes under 2 s.
  • Langton’s ant in FORTH walks on 128 × 60 quarter-character cells: on a clear cell it turns right, on a set one left, then flips the cell and steps forward. For about 10000 steps it makes a muddle, then it builds a diagonal highway and walks off the screen, at step 12024. ANT takes about 55 s.
  • Sieve of Eratosthenes in FORTH makes each of the numbers 0 to 7679 one quarter character, 128 to a row, all set to start with. The multiples of each prime up to 87 are cleared from its square on, and what is left are the primes: it counts 973. With 128 to a row the even numbers are whole columns, so the primes are in the odd ones. SIEVE takes about 60 s.
  • Bouncing balls in FORTH: six balls, 2 × 2 quarter blocks each, fall under gravity and bounce off the walls and floor. Each is drawn by flipping its pixels, so drawing it again rubs it out and balls that overlap pass through each other. Positions are kept in 256ths of a pixel, so a pixel is just the high byte, and lookup tables take the place of * and /, which are slow. About 23 frames a second.
  • Starfield in FORTH: sixteen stars fly out from the middle, each gaining speed every frame using only additions; the nearer ones are two pixels wide. About 10 frames a second.
  • Snake in FORTH: W A S D steer, Q stops. Each dot scores a point and adds three pieces of snake, and every fourth one speeds it up. A key while a program is busy resets the COMP80, and FORTH’s KEY waits, so the file starts by putting a little machine code into the dictionary: TICK has the calculator chip put out a number and halts for each of its twelve digit interrupts, about 7.5 ms, and returns the last key pressed or 0. A key that arrives during one of those HALTs is taken without a reset. The web page holds each key until the computer halts; on a real COMP80, or in MAME, a key pressed while the snake is being drawn may still reset it.
  • Maze in FORTH carves a maze of 42 × 29 rooms out of a solid screen by backtracking: from the room it is in it knocks through into a random room next door that is still solid, and when there is none it steps back the way it came. The way back is kept as one byte a step in a table of its own, not on the return stack, which is too small for 1218 rooms. A room is two quarter characters across and one down, with walls one thick, so a step of 3 across and 2 down comes out about square. A key then finds the way from the door on the left to the door on the right by filling in every dead end, and the rooms behind it as they become dead ends in turn, until only the way through is open. MAZE carves in about 34 s and fills in about 20 s; running it again makes a new maze.
  • Cellular automata in FORTH: a row of 128 cells, one quarter character each, starts with one live cell, and each generation is drawn on the next row down. A cell’s next state is bit L·4 + C·2 + R of the rule number, where L, C and R are it and its neighbours; the three slide along as one number from 0 to 7, doubled and masked at each cell, so no multiplying is needed. 30 RULE is chaotic, 90 RULE makes the Sierpiński triangle again and 110 RULE grows to the left. 60 generations take about 6 s.
  • Barnsley fern in FORTH starts a point at 0, 0 and moves it again and again by one of four maps that shrink and turn it, picked at random 1, 85, 7 and 7 times in 100; the points fill in a fern. It works in whole numbers with 36 as 1.0 and the maps’ factors in hundredths, which keeps every product below 32767, and a random byte is the top byte of a 16-bit LCG. FERN plots 5000 points in about 29 s.
  • Chaos game in FORTH, in the same file: a point moves half way towards one of the three corners of a triangle, picked at random, and a Sierpiński triangle appears out of the noise. Halving is a table lookup. CHAOS plots 6000 points in about 13 s.
  • Lissajous and spirograph curves in FORTH are traced from a sine table: a quarter of a sine wave is typed in as 65 numbers, and at load time it makes byte tables of c + a sin, so drawing only adds and looks up. 3 2 LISS traces x = sin 3t against y = sin 2t, 1024 points in about 2.5 s; PHASE shifts one against the other. 5 SPIRO is a wheel turning on a wheel, the small one 5 times as fast: x and y are each the sum of two waves. A key clears it.
  • Big digital clock in FORTH: 12 34 00 CLOCK sets the time and runs it. The COMP80 has no timer, so the clock counts TICKs, the same machine code as the snake game, which waits about 7.5 ms on the calculator chip: a second is drawing the time, then 115 TICKs, and one more TICK when the fraction in FR adds up. Timed over an hour in the emulator, it keeps time to about a second an hour; on a real COMP80 the chip’s own clock sets the speed, and W and FR can be changed. The digits are a 3 × 5 font with each dot 4 × 3 quarter blocks, worked out once when the file is typed in, so each second only copies them to the screen. TICK takes keys during its HALTs, so a key stops the clock cleanly.
  • Sorting in FORTH: SORTS draws 64 random bars and sorts them with a bubble sort, which compares neighbours and swaps them, each pass carrying the tallest bar left to the end: 2016 comparisons and 864 swaps, about 23 s. Then the same bars are sorted by quicksort, which puts the bars shorter than the last one to its left, the last one next to them, and sorts each side the same way: 459 comparisons and 167 swaps, about 5 s. A swap redraws only the part of each bar that changes. A key at the end clears it.

LISP

A small LISP 1.5 style interpreter, written for this project, in the 2 KB that held BURP, with garbage collection and dynamic scope. Press RS at READY; the top line changes to LISP. Type an expression and press Return to see its value. An expression can run over several lines: LISP keeps reading until the brackets balance.

GroupBuilt-ins
Special formsQUOTE (and 'x) COND LAMBDA DEFUN SETQ AND OR
ListsCAR CDR CONS LIST CADR CADDR
TestsATOM EQ NULL NUMBERP (true is T, false NIL)
Arithmetic+ - * / REM < >, two arguments each

OtherEVAL GC
  • Numbers are integers from −16384 to 16383. EQ compares numbers too.
  • (DEFUN SQ (X) (* X X)) sets SQ to (LAMBDA (X) (* X X)). A function is a value: (MAPCAR SQ L) passes it, and (F X) calls whatever F holds.
  • Variables are dynamically scoped, as in the original LISP: a function sees the variables of whatever called it, unless it has a parameter of the same name.
  • (PRINT x) prints x and a new line, (PRIN1 x) without one, (TERPRI) starts a new line and (TYO n) prints character code n. (GC) returns the number of free cells.
  • ; starts a comment. Errors print a message and the culprit: UNBOUND FOO, BAD FN 1, BAD ARG A, TOO DEEP, NO MEM.
  • Without the expansion there are 672 cells and recursion goes about 45 calls deep; with it, 7680 cells and about 140.

The examples

  • Symbolic differentiation is the program LISP was made for: an expression is a list, so DERIV can take it apart and build its derivative. (DERIV '(+ (* 3 (EXPT X 2)) (* 2 X)) 'X) gives (+ (* 6 X) 2).
  • Towers of Hanoi: move all but the bottom disc out of the way, move the bottom disc, move the rest back on top. (HANOI 4 'A 'C 'B) prints 15 moves.
  • Eight queens puts a queen in the first safe row of each column and backs up when a column has none. N is never passed to the inner functions: dynamic scope finds the N that QUEENS was called with.
  • Sierpiński triangle in LISP prints the same triangle, 16 rows of it, with TYO. With no bitwise AND, ODD looks at one bit at a time using REM and /. There are no loops either, so FROM calls a function on each number in a range by splitting the range in half: the recursion goes 5 deep for 16 numbers instead of 16. (SIER) takes about 6 s.
  • Hilbert curve in LISP can’t move a turtle about the screen, as LISP prints a line at a time. Instead D works out how far along the curve a point is: it looks at which quarter of the square the point is in, adds the points of the quarters before it, turns the point round to that quarter’s way up, and carries on with the quarter. Neighbouring points are joined when their distances differ by 1. ROW keeps the distances of the row below in BELOW with SETQ, so each point’s distance is worked out once. (HILBERT) takes about 30 s.
  • Eliza is a few rules of the 1966 program that played a psychotherapist. There is no READ, so you give TALK the sentence as a quoted list: (TALK '(I FEEL SAD ABOUT MY JOB)) answers (WHY DO YOU FEEL SAD ABOUT YOUR JOB). TALK finds the first keyword of RULES in the sentence and fills in its template with the rest of the sentence, I and YOU, MY and YOUR swapped. Every new word takes a place in the symbol table, so there is room for about 30 more.
  • Simplifying algebra shows what DERIV has to tidy up. D here differentiates without tidying, so (D '(* X X) 'X) gives (+ (* X 1) (* 1 X)); SIMP works from the inside out, adding up numbers, dropping 0s and 1s and turning (+ A A) into (* 2 A), and gives (* 2 X).
  • Permutations and the power set: PERMS puts each element in front of every order of the rest, and POWER is the subsets with the first element followed by those without it.
  • Fibonacci and Ackermann shows how much work recursion can do. CALLS counts the calls a function makes: the doubly recursive FIB takes 1973 calls for (FIB 15), where FAST takes 22. Then the limits: (FAST 22) overflows the 15-bit numbers, and (ACK 3 3) is too deep for the stack without the 32 KB expansion, with which it gives 61 in 2432 calls.
  • The animal game learns as it plays. TREE is a question with a yes tree and a no tree, or an animal. There is no READ, so you answer by calling functions: (PLAY) asks the first question, then (YES) or (NO). When it guesses wrong, (ITS 'DOG '(DOES IT BARK)) tells it the animal and a question that is yes for it. With no RPLACA, GROW builds a new tree along the path of answers, with the leaf it guessed replaced by the new question.
  • Unification finds values for the variables, written (? X), that make two expressions the same: (UNIFY '(F (? X) B) '(F A (? Y)) '(T)) gives (T ((? Y) B) ((? X) A)), and NIL when there are none. The bindings start with T so that no bindings can be told from failure. QUERY uses it the way Prolog does: for each goal it tries every clause in DB, with its variables renamed for the depth so they don’t clash, and goes on with the clause’s own goals. When none are left it prints the answer, then carries on looking for more. (QUERY '((GRAND TOM (? W)))) finds ANN and PAT in about 12 s.
  • LISP in LISP is the evaluator from the LISP 1.5 manual, cut down: EV takes an expression and a list of variables and their values, handles QUOTE, COND and LAMBDA itself, and passes anything else to AP with its arguments evaluated. AP knows CAR, CDR, CONS, EQ and ATOM, looks up any other name, and calls a LAMBDA by adding its parameters to the front of the list. As in the LISP underneath, scope is dynamic, so APP, given in ENV, can call itself: (EV '(APP (QUOTE (A B)) (QUOTE (C D E))) ENV) gives (A B C D E).
  • Missionaries and cannibals: three of each must cross a river in a boat that holds two, and the cannibals must never outnumber the missionaries on either bank. A state is (M C B), the missionaries and cannibals on the left bank and 1 if the boat is there. SOLVE searches depth first, never going back to a state it has been through. The five loads the boat can take are tried with one OR rather than a loop over a list, so each step of the search is only two calls deep and the 11 crossings fit in the stack. (CROSS) takes about 5 s and draws each state with TYO.
  • Roman numerals and number words: ROMAN takes the biggest value in its table that still fits, 1000 M, 900 CM and so on down to 1 I, and goes on with what is left. NUMERAL goes the other way, taking away a letter that comes before a bigger one. WORDS says a number the British way, with AND before the tens: (WORDS 1987) gives (ONE THOUSAND NINE HUNDRED AND EIGHTY SEVEN), and (WORDS 16383), the biggest number this LISP has, works too.

BASIC

COMP80 BASIC is a Tiny BASIC written for this machine, of the kind the small computers of 1976–79 had: integers only, numbered lines kept as typed, 26 variables and one array, in the 2 KB where BURP was. RS at READY enters it; a line with a number goes into the program, a line without one runs at once.

Statements

  • PRINT numbers and "strings": ; puts nothing between them, , moves to the next 16 columns, and one at the end keeps the line. AT X,Y moves to column X of line Y (1–31).
  • INPUT ["prompt";] V prints ? and reads a line; the answer can be any expression.
  • [LET] V = expression; IF condition [THEN] statement, or THEN a line number; GOTO, GOSUB, RETURN; FOR V = A TO B [STEP C] … NEXT V; REM; END. Statements on a line are separated by :.
  • PLOT X,Y and UNPLOT X,Y set and clear points, X 0–127 and Y 0–61 from the top left, four to a character in the quarter-block graphics; CLS clears the screen below the title.
  • RUN clears the variables and runs; LIST [line]; NEW. A line number on its own deletes that line.

Expressions

Numbers run from −32768 to 32767. + − * / (dividing rounds towards 0), brackets, and comparisons = < > <= >= <> that give 1 or 0. RND(N) is 1 to N, ABS(N), POINT(X,Y) is 1 if the point is set, and @(I) is an array in the memory after the program. Errors stop it with SYNTAX?, LINE?, DIVIDE?, MEMORY?, RETURN? or NEXT? and the line number. Any key stops a running program (the machine resets); RS comes back with the program kept.

The examples

  • Guess the number: RND picks a number from 1 to 100 and INPUT takes your guesses until you get it. As INPUT takes an expression, typing N wins straight away.
  • Primes marks the numbers below 500 in the array @() and clears the multiples of each prime from its square on, leaving 95. About 4 s.
  • String art draws 32 straight lines with a Bresenham subroutine at line 1000, which steps along the longer direction and moves in the other when the error grows too big; their envelopes make two curves. About 30 s.
  • Worm bounces a worm 24 points long round a box. Its positions go round a ring in @(), so each step it plots the new head and unplots the oldest point. It runs until a key.

Logo

Logo puts a turtle on the screen: a point with a position and a heading that draws as it moves. COMP80 Logo fits in the 2 KB where BURP was. RS at READY enters it; the top line shows LOGO and a ? prompt appears at the bottom. Lines 1–26 are the turtle's field, 128 × 52 quarter-block points with HOME in the middle; lines 27–31 are for typing and scroll by themselves. A step up or down is 0.6 of a point, as the points are taller than they are wide, so squares come out square. Numbers are 16-bit integers.

Commands

  • FD n, BK n move, drawing if the pen is down; RT n, LT n turn in degrees; SETH n sets the heading (0 is up); SETXY x y moves without drawing; HOME; CS clears the field and goes home.
  • PU, PD, PE: pen up, down, or rubbing out. SLOW n pauses at every step (0 to 255) so you can watch; WAIT n waits n sixtieths of a second.
  • REPEAT n [ … ]; IF test [ … ], or IF test [ … ] [ … ] with an else.
  • TO NAME :A :B … END defines a procedure, over as many lines as it takes (the prompt is > until END). STOP leaves it; OUTPUT x leaves it with a value, so it can be used in sums.
  • MAKE "X 5 sets a variable, read as :X. PRINT x, PRINT "WORD, PRINT [ ANY WORDS ]. RANDOM n is 0 to n − 1. ERALL forgets everything.
  • + - * / with * and / first, ( ), and < = > giving 1 or 0. A - after a space and before a digit is a negative number, so SETXY 0 -40 is two numbers. ; starts a comment.

Scope is dynamic, as in other Logos: a procedure sees the inputs of those that called it. A key while a program runs goes back to the monitor; RS comes back to Logo with the procedures kept.

The examples

  • Flower of squares: SQUARE draws a square of the size it is given, and FLOWER draws twelve, turning 30° between them. FLOWER takes about 3 s.
  • Twisting spiral keeps the side in a global variable and makes it 2 longer each time round; turning 91° instead of 90° makes the square spiral twist. SPIRAL 91 takes about 3 s; SPIRAL 121 makes a triangle spiral.
  • Recursive tree: a tree is a trunk with two trees on top, each two thirds the size, turned 30° each way. TREE stops below 5 steps and backs down its own trunk, so it ends where it started. FOREST takes about 3 s.
  • Koch snowflake: SIDE draws a side as four sides a third the length, turning 60° left, 120° right and 60° left between them, and calls itself for each until :N is 0. Three sides make the flake. FLAKE 3 takes about 5 s.
  • Random stars: five lines turning 144° make a star; SKY puts sixteen of random sizes at random places with RANDOM and SETXY. SKY takes about 2 s.

CHIP-8

CHIP-8 is the little virtual machine Joseph Weisbecker wrote for the COSMAC VIP in 1977, and its 64 × 32 display is exactly the COMP80’s screen: each pixel is one character, a solid block or a space. This ROM puts a CHIP-8 interpreter where BURP was. CHIP-8 memory is 0C00–1BFF, and programs start at CHIP-8 address 200, which is 0E00. Load one there from the monitor with LOAD 0E00, its bytes in hex and @, or from tape, then press RS to run it. While it runs, RS starts it again and FS goes back to the monitor.

Keys

The CHIP-8 keypad, 1 2 3 C / 4 5 6 D / 7 8 9 E / A 0 B F, is the block 1 2 3 4 / Q W E R / A S D F / Z X C V. The COMP80 keyboard says when a key goes down but not when it comes up, so a key counts as held for a third of a second after it is pressed, and holding it down keeps it held.

How it works

Every key is an interrupt, and the monitor goes back to READY unless the computer was waiting in a HALT. As in the Game of Life, the interpreter keeps its stack pointer in ROM, so the monitor finds a ROM word there pointing at the key handler with a HALT in front of it. What was interrupted is lost, so every CHIP-8 instruction can be started again: the registers are kept twice, an instruction works on a copy and makes it current with a single store, and DRW works out all the characters it will change before writing any. With no clock to read, it waits a little before each instruction, about 600 instructions a second, and the timers count down every 10 instructions. The wait is the byte at 1C00 (44): smaller is faster. There is no sound.

The examples

  • Bouncing ball draws a box round the edge, then moves the ball by drawing it again (which takes it off, since DRW uses XOR) and once more a step further on.
  • CHIP-8 keypad waits for a key with LD VA, K, then draws its digit from the built-in font four times as big, one bit at a time, and the number of presses in small digits with LD B, VE.
  • Dodge moves the ship with SKNP on keys 7 and 9 (A and D) and finds a crash from VF, which DRW sets when a pixel it draws was already on.
  • Kaleidoscope is a random walk with RND, drawn four times, mirrored.

The programs were assembled with chip8/tools/c8asm.py, which takes the mnemonics of Cowgod’s CHIP-8 reference.

FOCAL

FOCAL, short for FOrmula CALculator, was DEC's interactive language of 1968, a rival to BASIC. This one is written from scratch for the COMP80 and fills the 2 KB that held BURP. Like BURP it does its sums on the MM57109 calculator chip, so numbers are floating point with 8 digits, and the sines, logs and square roots are the chip's own. RS at READY enters it; the prompt is *.

A line typed without a number runs at once. A line with a number, group.step from 1.01 to 99.99, goes into the program; 1.1 is the same as 1.10, and a number alone deletes its line. Commands are known by their first letter, so T is TYPE and GO is GOTO, and several can share a line, separated by ;. As in FOCAL a program runs on from one group into the next, so it usually ends with QUIT.

Commands

  • TYPE "TEXT", !, E prints text, a new line and numbers. ASK "TEXT", V prints a colon and waits for a number for V; the answer can be any expression.
  • SET V=E. Variables are a letter and an optional letter or digit, and start at 0; names starting with F are functions.
  • IF (E) L1,L2,L3 goes to L1 if E is negative, L2 if it is 0 and L3 if it is positive; a line number left out means go on with the line.
  • GOTO L, and GO to run the program from the start. DO 2.1 runs a line and DO 2 a whole group, then come back; RETURN ends a DO early. QUIT stops.
  • FOR V=A,B,C; … runs the rest of the line with V = A, A+B, … up to C; FOR V=A,C counts in 1s.
  • COMMENT, WRITE lists the program, ERASE clears the variables and ERASE ALL the program too.

Expressions have + - * /, brackets, and ** for powers, since ^ is the RS key. The functions are FSQT FABS FSIN FCOS FEXP FLOG FITR FRAN: FLOG is the natural log, FITR the integer part and FRAN() a random number from 0 to 1. The chip's stack holds four numbers, so an expression can have at most four values waiting at once. It is as slow as BURP: a FOR loop goes round about seven times a second. Errors print ? and the line, as in ?01.20.

The examples

  • Square and cube roots prints FSQT(N) and N**(1/3) for 1 to 12, with DO 2 inside a FOR. About 10 s.
  • Celsius to Fahrenheit is one FOR line with a step of 10, from −20 to 100. About 4 s.
  • Compound interest ASKs for an amount, a rate and a number of years, and prints a line a year, rounded to the penny with FITR(P*100+.5)/100.
  • Guess the number: FRAN picks one from 1 to 100, and IF (G-N) goes to too small, right or too big. FRAN's seed is stirred by the time between key presses.
  • Sine wave prints, for each line, FITR(14+13*FSIN(X/3)) spaces with a FOR loop, then a star. About 45 s.

PILOT

PILOT was made in the 1960s and 70s for teachers to write lessons, quizzes and drills: a program types text, accepts an answer, matches it against the words it hopes for and jumps on. This PILOT is new, written for the COMP80 in the 2 KB where BURP was. Enter it with RS at READY.

Using it

  • A line starting with a number goes into the program in order of number; the number on its own deletes the line. LIST, RUN and NEW work on the program, and any other line runs at once.
  • A statement is a letter, then Y or N and a condition in brackets if wanted, a colon and the rest: T:HELLO, TY:RIGHT!, J(#Q<5):*ASK. A line can start with a label, *ASK.

Statements

  • T: types the text, with $N and #N replaced by the variables. A: accepts an answer; A:$N and A:#N also keep it. M: sets Y if any of its comma-separated words is in the answer, N if not.
  • J: jumps to a label, U: calls one as a subroutine and E: comes back, or ends the program. C: computes, C:#S=#S+1 or C:$N=TEXT. G:X,Y plots a point on 128 × 62 quarter blocks; G: clears the screen. R: is a remark.
  • Numbers are 16-bit integers with + - * / and brackets; ?12 is a random number from 1 to 12. Conditions compare with < > = <> <= >=. Variables are #A–#Z and $A–$Z; RUN clears them.

The examples

  • Greeting keeps your name in $N and uses M: to tell a good day from a bad one.
  • Capitals quiz marks every answer with the same subroutine, *MARK, which adds to the score with CY:.
  • Times tables asks five random questions on the table you choose and checks the answers with conditions.
  • Adventure is a little branching story: each place is a label, and the answers jump between them until you get home.
  • Drawing plots a box and its diagonals with G:, in under a second.

ZASM

ZASM is a Z80 assembler and disassembler in the 2 KB where BURP was, so you can write machine code in mnemonics instead of hex. RS at READY enters it; the top line shows ZASM and a > prompt. Numbers are in hex, as in the monitor, and only the first letter of a command counts.

Commands

  • DIS addr disassembles 24 instructions: address, bytes, instruction. DIS on its own carries on.
  • ASM addr assembles a line at a time. Each line starts with its address; type an instruction and Return and it is shown again as DIS shows it, or with a ? if it isn't one. A blank line ends, and DIS then lists what you typed.
  • GO addr calls a program; a RET comes back to ZASM.

Instructions are written as DIS shows them. Numbers must start with a digit (LD A,0FF), so that A to F are registers; relative jumps take the address jumped to (DJNZ 1007); index registers are (IX+5), (IY-2). Every documented instruction is covered, IX and IY included; there are no labels.

How it works

DIS splits each opcode into its fields, x, y and z, and a small table for each z picks a format string such as “LD r,n”, with codes for the operands. ASM is the disassembler run backwards: it tries every opcode in turn, and instead of printing the text it compares each character with the line you typed, giving up at the first mismatch. Where a number would be printed it reads yours and puts it in the instruction. The first opcode whose text matches is the one. The slowest, SET 7,(IY+7F), takes under a second.

The examples

  • The keyboard NMI handler disassembles the monitor at 0066: it checks it interrupted a HALT, reads the key from port 01, turns Return into 1F and jumps to 0800 for RS.
  • A pattern assembles a program that fills the screen with diagonal lines of quarter blocks, lists it and runs it; it waits for a key in a HALT.
  • A countdown assembles a loop that counts 9 down to 0 in the top line, half a second a digit.
  • Life, disassembled loads the Game of Life at 1000 and lists its start.

Prolog

A small Prolog, written for this project, in the 2 KB that held BURP. Press RS at READY; the top line changes to PROLOG. Type a clause to add it to the program, or a query starting ?- to have it answered; both end with a full stop and can run over several lines. For each answer Prolog shows the query’s variables (or YES); if there may be more it waits with ?: press ; for the next or any other key to stop. NO means no (more) answers.

Built-ins

  • Unifying: EQ(X,Y). Arithmetic: SUM(X,Y,Z) (any two known), TIMES(X,Y,Z), LESS(X,Y). Output: WRITE(X), NL. Control: !, FAIL.
  • With no lower case, a variable is a single letter or a letter followed by digits (X, L1); any other name is an atom. ? is an anonymous variable. Lists are [1,2,3] and [H:T], as | can’t be typed.
  • There are no operators: arithmetic is done with relations, as in micro-PROLOG. SUM(X,1,N) gives N − 1. There is no NOT, but NOTIN(X,L) :- MEMBER(X,L), !, FAIL. and NOTIN(?,?). make one.
  • Numbers are integers from −16384 to 16383. % starts a comment. Errors: SYNTAX, NO MEM, TOO DEEP.
  • Nothing is garbage collected: the heap is given back on backtracking and after each query. Without the expansion a query can make about 40 steps without backtracking and keep about 100 choice points; with it, about 400 and 600.

How it works

Clauses are kept as they are read, and a query is answered depth first: each goal is unified with the head of each clause of the same name in turn, the clause’s variables made new on the heap, and its body goes in front of the goals still to do. A choice point, saying where to carry on and how much of the heap and the trail to give back, is kept only when another clause of the same name follows, so a predicate whose last clause matches leaves none. Backtracking undoes the bindings on the trail.

The examples

  • A family tree: PARENT facts, and FATHER, GRAND and ANCESTOR rules; ANCESTOR calls itself, so ?- ANCESTOR(X,GUS). finds four ancestors one ; at a time.
  • Lists: APPEND, MEMBER, REVERSE and LENGTH. APPEND works both ways: ?- APPEND(X,Y,[1,2,3]). finds the four ways to split the list.
  • Colouring a map: five countries and three colours, and Prolog tries colours until no two neighbours are the same, backing up when a pair clashes.
  • Finding a way between two towns without going through a town twice, keeping the towns so far in a list and testing it with a NOTIN made of cut and FAIL.
